1 High PII 마스킹 사각지대 섹션 9 · privacy.ts

stripPrivateData()는 14개 하드코딩 정규식으로만 민감 정보를 탐지합니다. 다음은 현재 패턴에 포함되지 않아 그대로 KV에 저장됩니다.

  • 주민등록번호 / 이메일 / 전화번호 / 주소 등 개인 식별 정보 (PII)
  • 20자 미만의 짧은 비밀번호 · API 키 (api_key=short123 형태는 통과)
  • 사용자 정의 내부 토큰 (조직 특화 접두사)
⚠실제 위험 — DB 조회 결과, 파일 내용, 환경변수 출력 등이 tool output으로 캡처될 때 주민번호·이메일이 mem:obs:{sessionId}에 평문으로 저장될 수 있습니다. 이 데이터는 LLM(Qwen) 압축 요청 payload에도 포함됩니다.
💡완화책 — 민감 내용을 Claude에 직접 노출하지 않거나, <private>내용</private> 태그로 명시적으로 감싸면 패턴 무관하게 [REDACTED]로 치환됩니다.
2 High PII 패턴 확장 불가 섹션 9 · privacy.ts:5-20

패턴 목록이 src/functions/privacy.ts에 하드코딩되어 있고, 환경변수로 커스텀 패턴을 추가하는 방법이 없습니다.

  • SECRET_PATTERN_SOURCES 등의 env 확장점은 존재하지 않습니다
  • 조직 특화 내부 토큰(예: 사내 SSO 토큰, 업무용 API 키)을 추가하려면 소스 수정 후 재빌드 필요
  • Fork 없이는 upstream 업데이트와 패턴 커스터마이징을 동시에 유지하기 어렵습니다
💡현실적 대안 — src/functions/privacy.ts 직접 수정 후 재빌드하거나, 민감 작업은 AGENTMEMORY_AUTO_COMPRESS=false인 별도 프로젝트 세션에서 격리 운영하는 방법을 검토하세요.
3 High 기본 무인증 오픈 섹션 9 · 섹션 12 · .env AGENTMEMORY_SECRET

AGENTMEMORY_SECRET를 설정하지 않으면 REST API(:3111)와 Viewer(:3113)가 loopback에서 무인증으로 열립니다.

  • 동일 머신에서 실행 중인 다른 프로세스가 인증 없이 전체 메모리 DB에 접근 가능
  • 팀 공유 머신, 원격 개발 환경(codespace, 사내 VM)에서는 심각한 노출 위험
  • 기본값이 "비활성"이라 사용자가 별도 설정하지 않으면 노출 상태를 인지하기 어려움
⚠즉시 조치 — ~/.agentmemory/.env에 AGENTMEMORY_SECRET=강한-랜덤-문자열을 추가하세요. 설정 후 Bearer 토큰 인증이 활성화되어 외부 접근이 차단됩니다.

5 Medium stale-session 자동 reaper 없음 섹션 8 · observe.ts

크래시로 Stop/SessionEnd 훅이 실행되지 않은 세션은 상태가 "active"로 남습니다. 이를 자동으로 감지해 "abandoned"나 "ended"로 전환하는 백그라운드 reaper가 없습니다.

  • 잔류한 active 세션은 다음 세션 시작 시 context 주입에서 "현재 세션"과 혼동될 수 있음
  • session 목록/통계 조회 시 종료된 세션이 active로 집계됨
  • 대량 크래시 이력이 쌓이면 mem:sessions KV가 오염됨
⚠현재 상태 — 자동 수정 방법이 없습니다. POST /agentmemory/session/end를 수동 호출하거나, 재임포트 후 상태를 직접 정리해야 합니다.
6 Medium 자동 스냅샷 없음 섹션 8 · .env SNAPSHOT_ENABLED

SNAPSHOT_ENABLED=true로 설정해도 코드 내부에 자동 setInterval이 없습니다. POST /agentmemory/snapshot-create를 외부에서 주기적으로 호출해야만 state_store.db 백업이 생성됩니다.

  • 사용자가 외부 cron 또는 별도 스크립트를 직접 설정해야 함
  • SNAPSHOT_INTERVAL env 변수는 존재하지만 이를 내부에서 읽어 interval을 만드는 코드가 없음
  • DB 손상 · 디스크 오류 시 마지막 스냅샷 이후 모든 기억이 유실됨
💡권장 조치 — 시스템 crontab에 curl -X POST http://localhost:3111/agentmemory/snapshot-create -H "Authorization: Bearer $SECRET"를 1시간마다 등록하거나, launchd(macOS)로 주기 실행을 설정하세요.
7 Medium Stop 훅 의존성 — 정상 종료 필수 섹션 8 · stop.ts · session-end.ts

요약(mem::summarize), 그래프 추출(mem::graph-extract), insight 합성(mem::slot-reflect), 4-tier 통합(mem::consolidate-pipeline)은 모두 Stop 또는 SessionEnd 훅이 정상 실행된 이후에만 트리거됩니다.

  • 짧은 탐색 세션이나 인터럽트가 잦은 워크플로에서는 유익한 세션이 누락될 수 있음
  • 2시간 주기 consolidation은 데몬이 살아있는 동안만 동작 — 재시작 시 간격 리셋
💡권장 습관 — IDE 창을 닫거나 터미널을 종료하기 전에 Claude Code의 /stop 명령으로 세션을 정상 종료하면 파생 데이터 생성이 보장됩니다.

C검색 품질

8 Medium smart-search에 importance 필터 없음 섹션 10 · hybrid-search.ts · context.ts

context 주입 단계에서는 importance ≥ 5 강제 필터가 적용되지만, mem::smart-search와 mem::search에는 이 필터가 없습니다. 모든 인덱싱된 관측이 BM25/벡터/그래프 점수로 경쟁합니다.

  • 합성 압축 경로(AUTO_COMPRESS=false)에서 생성된 관측은 importance=5 고정, confidence=0.3 고정으로 품질 구분이 무의미
  • 저품질 관측(중복, 단순 탐색 등)이 직접 검색 결과 상위에 오를 수 있음
  • 검색 품질 방어는 context 주입 단계에서만 강하게 작동하고, API 직접 호출에는 약함
💡현실적 대안 — LLM 압축(AUTO_COMPRESS=true)을 켜서 Qwen이 importance를 직접 채우게 하거나, mem::evict의 lowImportanceThreshold를 높여 저품질 관측을 주기적으로 정리하세요. 검색 정밀도가 부족하다면 RERANK_ENABLED=true로 cross-encoder 재정렬을 활성화하세요.
9 Medium 관측 상한 초과 시 묵시적 차단 섹션 8 · config.ts:145 · observe.ts

MAX_OBS_PER_SESSION(기본 500) 초과 시 observe 요청은 {success: false}를 반환하며 기존 데이터는 삭제하지 않고 새 관측만 차단합니다. 사용자 입장에서는 세션이 "조용히 기억하지 않는" 상태가 됩니다.

  • 긴 코딩 세션(수백 개 tool 호출)에서 후반부 관측이 통째로 누락됨
  • 훅 스크립트는 실패 응답을 로그에 남기지만, 일반 사용 중에는 인지하기 어려움
  • 또한 동일 이름이 두 곳에 다른 값으로 존재: import 검증 상한은 하드코딩 5,000 (export-import.ts:190), 런타임 쓰기 한도는 env 500 (config.ts:145)
⚠혼동 주의 — MAX_OBS_PER_SESSION=500은 eviction 상한이 아닙니다. 초과 시 삭제가 아닌 쓰기 거부입니다. 긴 세션이 예상된다면 ~/.agentmemory/.env에서 값을 높여두세요.

D성능 · 확장성

10 Medium 벡터 검색 brute-force top-k 섹션 5 · hybrid-search.ts

벡터 검색은 HNSW·IVF 등의 ANN(Approximate Nearest Neighbor) 인덱스 없이 전체 벡터에 대한 코사인 유사도를 순차 계산합니다. 관측이 누적될수록 검색 지연이 선형 증가합니다.

  • 적은 세션(~수백 개 관측)에서는 문제 없음
  • 장기 사용 + 다수 프로젝트 운영 시 스마트 서치 응답 시간 증가 예상
  • RERANK_ENABLED=true까지 켜면 벡터 스캔 + cross-encoder 재정렬이 중첩되어 지연 누적
11 Low Viewer 힘 시뮬레이션 O(n²) 섹션 5 · index.html · runSimulation()

Viewer(:3113)의 그래프 레이아웃은 d3/vis/cytoscape 없이 커스텀 HTML5 Canvas로 직접 구현되어 있습니다. Coulomb 척력 계산이 O(n²) — 노드 수 제곱에 비례해 CPU 부하가 증가합니다.

  • 수십 개 노드까지는 쾌적하나, 수백 개 이상이 되면 브라우저 탭 CPU 사용률 급증
  • 감쇠 0.9로 시뮬레이션이 멈추지 않으면 지속적으로 계산이 일어남
  • 외부 그래프 라이브러리(d3-force, cytoscape) 미사용으로 최적화 여지가 제한됨
12 Medium tool 호출마다 LLM 비용 발생 섹션 3 · compress.ts · 섹션 0 설정

AGENTMEMORY_AUTO_COMPRESS=true 설정 시 PostToolUse 이벤트마다 Qwen LLM을 1회 호출합니다. 활발한 코딩 세션에서는 수십~수백 회의 LLM 호출이 발생합니다.

  • LiteLLM 프록시에 요청 부하 누적 — rate limit에 걸릴 수 있음
  • tool 호출 응답 대기 시간과 별도로 압축 비용이 중첩 (비동기지만 세션 종료 처리에 영향)
  • LLM 비용 유료 제공자 사용 시 관측 수 × LLM 비용이 직접 과금
  • 합성 압축 대비 품질이 높지만, 경량 작업(파일 탐색, 간단한 read) 관측도 동일 비용 소모
💡트레이드오프 — 비용/지연이 부담스러우면 AGENTMEMORY_AUTO_COMPRESS=false로 전환하세요. 합성 압축은 LLM 없이 즉시 완료되지만 facts=[], concepts=[], importance=5 고정으로 품질이 낮아집니다. 중간 지점으로 SUMMARIZE_CHUNK_CONCURRENCY를 낮춰 동시 요청 수를 제한하는 방법도 있습니다.
