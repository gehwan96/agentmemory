1전체 아키텍처 개요

agentmemory는 세 레이어로 구성됩니다: Claude Code(훅)가 이벤트를 보내면 → agentmemory 데몬(REST :3111)이 비즈니스 로직을 처리하며 → iii-engine(WebSocket :49134)의 워커들이 실제 저장을 담당합니다.

전체 시스템 구성. ✦ 표시 함수는 외부 LLM API를 호출함(provider 키 필요). 임베딩은 별도 로컬 경로.

2데이터 수집 (Ingestion)

AI 코딩 세션의 모든 이벤트는 Claude Code의 12개 훅이 캡처합니다. 각 훅 스크립트는 stdin에서 이벤트 JSON을 읽어 데몬에 HTTP POST합니다. src/hooks/*.ts

🛡재진입 가드 — 각 훅 스크립트는 실행 시 AGENTMEMORY_SDK_CHILD=1 환경변수 또는 entrypoint==="sdk-ts"를 감지하면 즉시 종료합니다. Stop 훅이 summarize를 호출할 때 내부에서 다시 Stop이 트리거되는 재귀 루프를 방지하는 장치입니다. src/hooks/stop.ts:6

데이터 모델 계층

agentmemory의 핵심 데이터 타입은 4계층입니다. 상위로 갈수록 더 요약되고 오래 보존됩니다. src/types.ts

Session(임시) → RawObservation(캡처) → CompressedObservation(인덱싱됨) → Memory(영속 학습)

JSONL Replay / Import 경로

라이브 훅 외에, Claude Code 세션 기록(~/.claude/projects/**/*.jsonl)을 사후 임포트할 수 있습니다. src/functions/replay.ts src/replay/jsonl-parser.ts

  • 엔드포인트: POST /agentmemory/replay/import-jsonl → 202 Accepted (비동기)
  • jsonl-parser가 transcript 항목 타입별로 hookType 매핑: user.text → prompt_submit, user.tool_result → post_tool_use/failure, assistant.text → stop, assistant.tool_use → pre_tool_use
  • project는 cwd의 마지막 경로 세그먼트에서 자동 추출
  • 파일당 합성 압축으로 인덱싱 (LLM 없이 빠르게)
  • 세션에서 Crystal(파일/툴/레슨 묶음) + Lesson(always/never/prefer 패턴 정규식으로 마이닝) 자동 파생
  • 안전장치: 최대 200개 파일(MAX_FILES_DEFAULT), 민감 경로 거부(isSensitive), 심링크 거부, 탐색 캡(traversalCap)

3압축 (Compression)

모든 RawObservation은 CompressedObservation으로 변환되어야 BM25 · 벡터 인덱스에 올라갑니다. 두 가지 경로가 있습니다.

AUTO_COMPRESS=true 설정 시 오른쪽 경로(외부 LLM API). 기본값은 왼쪽 합성 압축(zero-LLM)입니다.

세션 요약 — Summarize Map-Reduce

Stop 훅 → mem::summarize가 호출됩니다. 관측 수가 많으면 청크로 나눠 병렬 처리합니다. src/functions/summarize.ts

SUMMARIZE_CHUNK_SIZE=400, SUMMARIZE_CHUNK_CONCURRENCY=6. 50% 이상 청크 실패 시 중단(MAX_SKIP_RATIO=0.5).

4통합·반영 (Consolidation & Reflection)

단기 관측들을 장기 지식으로 증류하는 단계입니다. CONSOLIDATION_ENABLED=true 설정에 의해 세션 종료 시와 2시간마다 자동 실행됩니다.

⏱트리거 두 가지 — (1) 세션 종료 시 SessionEnd 훅 → POST /consolidate-pipeline?force=true (즉시, 강제). (2) 백그라운드 setInterval 매 2시간(CONSOLIDATION_INTERVAL_MS=7200000) — 데몬이 살아있는 동안 자동 반복.

4-tier 파이프라인

consolidation-pipeline.ts:50 기준. REFLECT=true 덕분에 Tier 2도 활성화됨.

세션 종료 시 Reflection (REFLECT=true)

위 4-tier와는 별도로, Stop 훅 → event::session::stopped 이벤트 → mem::slot-reflect가 추가로 호출됩니다.

  • 그래프 노드/엣지 + semantic 사실 + lesson + crystal을 로드
  • BFS depth≤2로 개념 클러스터 구성 (그래프 없으면 Jaccard 0.3 임계값 공출현 클러스터)
  • 클러스터당 ≥3 아이템 → 외부 LLM API에 "2개 이상 소스에서 공통되는 상위 원칙" 요청
  • content fingerprint로 dedup: 기존 insight는 confidence += 0.1, 신규는 KV:mem:insights에 저장
  • 최대 5개/클러스터, 총 50개 상한
💡decay 수식 — decayPeriods = floor(daysSince / 30) → newStrength = max(0.1, strength × 0.9^decayPeriods). 30일 비활성이면 0.9배, 60일이면 0.81배. 하한 0.1로 완전 소멸은 없음.

5그래프 (Graph Extraction & Retrieval)

지식 그래프 추출

세션 Stop 시 batch로 실행됩니다. 개별 remember 호출마다 추출하지 않습니다. src/functions/graph.ts src/triggers/events.ts:59-66

graph.ts:93-178. 외부 LLM API가 각 관측을 읽고 개념 간 관계를 XML로 출력합니다.

검색 융합 — RRF (Reciprocal Rank Fusion)

smart-search는 단순 가중 합산이 아니라 순위 기반 융합입니다. 각 스트림의 원점수가 아닌 순위를 사용합니다. src/state/hybrid-search.ts

hybrid-search.ts:77-240. 원점수가 아닌 순위(rank)를 융합하므로 스케일 차이에 강건합니다.

Viewer — 그래프 시각화 (:3113)

  • 단일 index.html 자체완결 앱 (~197KB). 외부 그래프 라이브러리 없음 (d3/vis/cytoscape 미사용)
  • HTML5 <canvas> 2D 직접 구현 — 커스텀 힘 기반 시뮬레이션(runSimulation()): O(n²) Coulomb 척력 + Hooke 인력(목표거리 100) + 중심 중력, 감쇠 0.9
  • 노드 shape-by-type: file→rect, function/concept/pattern→circle, error/decision→diamond, library→hexagon
  • REST 프록시: 모든 요청은 3113→3111로 relay, bearer token은 서버측에서만 첨가 (브라우저에 secret 노출 없음)
  • 실시간: WebSocket stream/mem-live/viewer 우선, 실패 시 HTTP 폴링 폴백
  • 빈 그래프 → "Rebuild Graph" 버튼 → POST graph/build → mem::graph-build (전체 관측에서 재구성)

6저장 (Storage)

agentmemory는 디스크에 직접 접근하지 않습니다. 모든 저장은 iii-sdk RPC (state::get/set/update/delete/list)로 iii-state 워커에 위임합니다. src/state/kv.ts

stream_store(:3112)는 Viewer가 소비하는 파생/휘발성 라이브 테이프입니다 — 진실의 원천이 아님.

인덱스 영속화 및 부팅 시 복구

  • BM25 인덱스 + 384-dim 벡터 → mem:index:bm25 스코프에 직렬화 blob으로 저장, 5초 디바운스로 쓰기 빈도 제어
  • 부팅 시 dim guard: 로드된 벡터의 dimension ≠ 384이면 거부. AGENTMEMORY_DROP_STALE_INDEX=true 설정 시 강제 초기화 후 재색인
  • BM25 비어있으면 백그라운드에서 전체 rebuildIndex(kv) 실행 (배치 크기 32, REBUILD_EMBED_BATCH_SIZE)
  • 벡터 임베딩은 @xenova/transformers lazy-load: 첫 임베딩 요청 시 모델 파일 다운로드 및 캐시
📐임베딩 독립성 — EMBEDDING_PROVIDER=local은 LLM 제공자 감지 경로와 완전히 별도입니다. OPENAI_API_KEY가 LLM으로 감지되어도 임베딩은 Xenova 로컬 모델을 강제 사용합니다. 이 값을 변경하면 384-dim 불일치로 dim guard가 발동하니 인덱스 초기화가 필요합니다.

7내 설정 기준 전체 흐름 종합

위 모든 단계가 실제 세션에서 어떻게 연결되는지를 한 장으로 정리합니다.

전체 파이프라인 흐름. 회색 화살표는 단계 연결, 색상 박스는 LLM 경로(옵트인, provider 키 설정 시 활성화).

✅요약 — agentmemory가 제공하는 가장 완전한 학습 모드입니다. 매 tool 호출(외부 LLM 압축, 옵트인) → 세션 종료(요약·그래프·insight·4-tier 통합) → 2시간 주기 통합이 모두 활성화됩니다. 임베딩만 로컬(Xenova 384-dim)이므로 임베딩 미지원 이슈와 무관하게 하이브리드 벡터 검색이 동작합니다.

8데이터 수명주기 & 소멸 경로

Q. "매 세션이 종료되어야만 정상 동작하는가?"

아닙니다. 라이브 관측은 세션 종료와 무관하게 훅 이벤트마다 즉시 영속됩니다. 세션 종료(Stop/SessionEnd)에서만 일어나는 것은 파생 데이터입니다.

인덱스 손실은 rebuildIndex()로 자동 복구됩니다. 요약·그래프·교훈은 재생성 불가.

⚠오해 정정 — MAX_SESSIONS / MAX_MEMORIES 등 6개 상수
이 상수들은 src/functions/export-import.ts:187-192에 정의된 import 검증 상한입니다. 주기적 eviction(삭제)과 전혀 무관합니다. import 데이터가 이 값을 초과하면 삭제가 아니라 import 자체를 거부하고 에러를 반환합니다.

또한 동일한 이름 MAX_OBS_PER_SESSION이 두 곳에 별도 존재합니다:
  • import 검증: export-import.ts:190 하드코딩 5,000
  • 런타임 쓰기 한도: env MAX_OBS_PER_SESSION 기본 500 (config.ts:145) — observe 시 쓰기를 차단, 기존 데이터는 삭제하지 않음

eval 지표 (검색 품질 측정)

eval/ 디렉토리가 실제 품질을 측정합니다. eval/runner/score.ts:13-32

  • precision@k: 상위 k개 결과 중 정답 비율
  • recall@k: 정답이 상위 k개 안에 포함될 확률
  • hit@k: 정답 세션 ID가 상위 k개 세션 중 하나인지
  • topGoldRank: 첫 번째 골드 세션의 랭크 (낮을수록 좋음)
  • 비교 어댑터: agentmemory 하이브리드 vs grep-only vs 벡터-only
💡권장사항 —
  • 검색 품질이 떨어진다고 느껴지면 RERANK_ENABLED=true를 시도하세요. 로컬 Xenova reranker(ms-marco-MiniLM-L-6-v2)가 추가로 돌므로 지연은 증가하지만 정밀도가 올라갑니다.
  • 세션 요약이 충분히 쌓인 상태(≥5)에서 consolidation Tier 1(semantic merge)이 실행되면 mem:semantic에 공통 사실이 쌓여 context 품질이 눈에 띄게 향상됩니다.
  • importance가 낮은 관측이 검색 결과를 오염한다고 느끼면 현재 코드 구조상 observe 시 importance를 높이거나 (LLM 압축 품질 향상), 수동으로 mem::evict의 lowImportanceThreshold를 올려 저중요도 관측을 정리하는 것이 현실적인 대안입니다.

11설정 튜닝 가이드

검색 가중치 (BM25 / VECTOR / GRAPH) — "올리면 뭐가 바뀌나"

📐핵심 원리 — 가중치는 절대값이 아니라 참여 스트림 간 비율로 작동합니다. 스트림(BM25/vector/graph)이 빈 경우 해당 가중치를 0으로 만들고 나머지를 합이 1이 되도록 재정규화합니다(hybrid-search.ts:197-206). 따라서 BM25=0.4/VECTOR=0.6을 각각 2배로 올려도 결과는 동일합니다.

가중치는 재정규화되므로 비율만 의미 있음. BM25:VECTOR = 0.4:0.6 = 2:3 (동일 효과).
