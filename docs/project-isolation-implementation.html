agentmemory
project 격리 구현

단일 인스턴스로 50+ 레포의 메모리를 자동 분리한다

agentmemory fork(feat/project-isolation)에 project 필드를 추가해 cwd 기반으로 메모리를 자동 격리한 C안의 실제 구현 기록이다. 10개 커밋, 10개 소스 파일, 19개 신규 테스트.

이 문서에 대해

이 문서는 agentmemory 멀티 레포 운영 가이드에서 제안한 C안을 실제로 rohitg00/agentmemory fork(v0.9.21)에 적용한 구현 결과다. 가이드가 v0.x 기준 추정이라 코드와 일치하지 않는 부분이 있었으며, 이 문서는 실제 코드 기준으로 그 차이를 정리한다.

배경

왜 C안이었나

/Users/nhn/project/ 하위 50+ 레포(개인·회사 혼재)에 Claude Code를 사용하는데, agentmemory가 단일 글로벌 KV 구조라 모든 레포의 메모리가 한 SQLite에 섞인다.

방안 A
별도 인스턴스
레포마다 포트를 달리해 agentmemory를 각각 실행. 완전한 물리 격리지만 50+ 레포 × 포트 운영이 무거워진다.
방안 B
concepts 태그
메모리 저장 시 [repo:알림톡] 같은 태그를 붙이는 규약. 에이전트 규율에 의존해 누락 위험이 있다.
방안 C ✓
fork + project 필드
단일 인스턴스를 유지하면서 Memory.project 필드로 논리적 격리. cwd에서 자동 추론하므로 에이전트 규율 불필요.

설계 검토

가이드 vs 실제 코드

원본 가이드는 v0.x 기준 추정으로 작성됐고, v0.9.21 실제 코드와 중요한 차이가 있었다. 본 구현은 실제 코드 기준으로 작성됐다.

가이드의 주장실제 코드 (v0.9.21)함의
SQLite ALTER TABLE로 컬럼 추가 필요 iii-sdk KV 추상화 위에 JSON 객체 저장. DB 스키마가 없음 TS 인터페이스에 필드 추가만으로 끝. 자동 역호환
inferProjectFromCwd()로 자동 추론 MCP 핸들러에 cwd 컨텍스트가 없음 (자기 cwd만 보임) session-start hook이 cwd→project 매핑 저장 중 → sessionId로 우회
검색 핸들러에 project 필터 신규 추가 mem::search, mem::smart-search, mem::lesson-recall이 이미 project? 파라미터 보유 신규 도입이 아니라 미완성 격리를 완성하는 작업 → 상류 PR 친화적
ROADMAP 미언급 ROADMAP.md:55에 "Cross-agent shared memory namespace" 미해결로 명시 상류 PR 머지 가능성 ↑
mem::remember 항목 특수 처리

기존 코드의 검색 필터는 Session.project 기반이라 KV.sessions에 세션이 없는 mem::remember 직접 저장 항목을 처리 못했다. 이 구현은 세션을 못 찾을 때 KV.memories에서 Memory.project를 직접 비교하는 fallback 경로를 추가했다.

두 종류 관찰 엔트리

① 일반 session 관찰

session-start/stop hook이 생성한 관찰. KV.sessions[sessionId]에 연결되어 있으므로 Session.project를 통해 필터링.

② mem::remember 직접 저장

memory_save가 생성하는 KV.memories[id] 항목. 세션 없이 독립 존재하므로 Memory.project 직접 비교.

project=undefined 정책: 어느 쪽이든 project가 undefined인 항목은 모든 project 검색에서 통과된다 — 공용 레거시 레이어로 동작한다. 이전에 import하거나 project 이전에 저장된 메모리가 여기에 해당한다.

핵심 코드 스니펫

① resolveProject 헬퍼

src/mcp/resolve-project.ts
import type { StateKV } from "../state/kv.js";
import type { Session } from "../types.js";
import { KV } from "../state/schema.js";

export async function resolveProject(
  sessionId: string | undefined,
  kv: StateKV,
): Promise {
  if (!sessionId) return "default";
  const session = await kv.get<Session>(KV.sessions, sessionId);
  if (!session) return "default";
  return session.project || "default";  // || handles empty string
}

③ smart-search.ts post-filter 블록

src/functions/smart-search.ts (발췌)
let filteredResults = hybridResults;
if (data.project) {
  const projectFilter = data.project;
  const filtered = await Promise.all(
    hybridResults.map(async (r) => {
      // mem::remember 항목: Memory.project 직접 비교
      const mem = await kv.get<Memory>(KV.memories, r.observation.id).catch(() => null);
      if (mem !== null && mem !== undefined) {
        if (mem.project !== undefined && mem.project !== projectFilter) return null;
        return r;
      }
      // 일반 session 관찰: Session.project 비교
      const session = await kv.get<Session>(KV.sessions, r.sessionId).catch(() => null);
      if (session) {
        if (session.project !== projectFilter) return null;
        return r;
      }
      return null;  // 세션도 메모리도 없으면 제외
    })
  );
  filteredResults = filtered.filter((r): r is HybridSearchResult => r !== null);
}

④ memory_recall_global 핸들러

src/mcp/server.ts (memory_recall_global case 발췌)
case "memory_recall_global": {
  const limit = Math.max(1, Math.min(100, asNumber(args.limit, 10) ?? 10));
  const projects = parseCsvList(args.projects);

  // projects 미지정: project 필터 없이 전체 검색
  if (projects.length === 0) {
    const result = await sdk.trigger({
      function_id: "mem::smart-search",
      payload: { query: args.query, limit },
    });
    return { status_code: 200, body: { content: [{ type: "text",
      text: JSON.stringify(result, null, 2) }] } };
  }

  // projects 지정: 병렬 검색 후 병합 (undefined 항목은 각 project 필터에서 자동 통과)
  const perProject = await Promise.all(
    projects.map((project) =>
      sdk.trigger({ function_id: "mem::smart-search",
        payload: { query: args.query, limit, project } })
        .then((r) => (r as { results?: CompactResult[] }).results ?? [])
        .catch(() => []),
    ),
  );

  // obsId 기준 중복 제거, 높은 score 우선
  const seen = new Map<string, CompactResult>();
  for (const results of perProject)
    for (const r of results)
      if (!seen.has(r.obsId) || r.score > seen.get(r.obsId)!.score)
        seen.set(r.obsId, r);

  const merged = Array.from(seen.values())
    .sort((a, b) => b.score - a.score).slice(0, limit);

  return { status_code: 200, body: { content: [{ type: "text",
    text: JSON.stringify({ mode: "compact", results: merged }, null, 2) }] } };
}

시나리오 1 — 프로젝트별 격리 검색

레포 A와 B에서 각각 메모리를 저장하면, 기본 검색 도구로는 자기 레포 메모리만 보인다.

레포 A (cwd = /Users/nhn/project/Alimtalk)
// SessionStart hook이 자동으로 Session.project = "Alimtalk" 저장
memory_save({ content: "알림톡 API 인증 헤더는 X-NCP-APIGW-API-KEY 사용", type: "fact", sessionId: "<현재세션ID>" })
// → Memory { project: "Alimtalk", ... } 저장됨
레포 A에서 memory_smart_search("API 인증") → ✓ Alimtalk 메모리 보임
레포 B에서 memory_smart_search("API 인증") → ✗ Alimtalk 메모리 안 보임

시나리오 2 — 공용 레거시 메모리 (project=undefined)

import하거나 project 적용 이전에 저장된 메모리는 project=undefined라 모든 레포에서 보인다.

import 또는 기존 데이터
// project 필드 없이 저장된 Memory
{ id: "mem-abc", content: "자주 쓰는 curl 명령어 모음", project: undefined }

// project 필터가 "Alimtalk"여도 통과됨
// → 레거시 공용 레이어로 모든 레포에서 보임
활용 팁: 마이그레이션 시 기존 메모리를 memory_export → wipe → 선별 재import하면 project=undefined로 들어가 공용 레거시가 된다. 레포 구분 없이 공유하고 싶은 메모리(공통 CLI 팁, 범용 패턴 등)를 여기 넣으면 좋다.

시나리오 3 — cross-project 조회 (memory_recall_global)

레포를 넘나드는 검색이 필요할 때는 memory_recall_global을 사용한다. 기본 도구와 달리 project 격리를 우회한다.

어느 레포에서나 호출 가능
// 전체 프로젝트 검색 (project 필터 없음)
memory_recall_global({ query: "API 인증", limit: 20 })
// → Alimtalk, nc-notification-email, tc-notification, undefined 항목 모두 반환

// 특정 프로젝트만 (+ 공용 레거시 자동 포함)
memory_recall_global({ query: "API 인증", projects: "Alimtalk,nc-notification-email" })
// → Alimtalk + nc-notification-email + undefined 항목 반환
// → 내부적으로 두 project를 병렬 검색 후 obsId 기준 중복 제거, score 정렬

운영

마이그레이션 — export → wipe → 재시작

  • 1
    백업: memory_export로 전체 메모리를 JSON 파일로 저장. 이 파일은 wipe 후에도 별도 보관.
  • 2
    wipe: agentmemory 데이터 디렉토리를 백업 후 초기화. export 파일은 별도 유지.
  • 3
    fork 빌드 적용: npm run build 후 MCP 클라이언트에서 재시작 (claude mcp restart agentmemory).
  • 4
    자연 축적: 각 레포에서 Claude Code를 사용하면 새 메모리가 자동으로 project: <레포이름>으로 쌓이기 시작.
  • 5
    선택적 import: 백업 export에서 의미 있는 메모리만 골라 import. 이때 모두 project=undefined로 들어가 공용 레거시 레이어로 모든 레포에서 보임.
데이터 격리 주의

정책상 회사·개인 레포가 같은 SQLite를 공유한다. 회사 코드 내용이 메모리에 저장될 수 있다는 점을 인지하고, 물리적 분리가 필요하다면 별도 인스턴스(방안 A) 또는 다른 접근이 필요하다.
